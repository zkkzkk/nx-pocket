# Halfold 设计

## 1. 目标与边界

**要做的**：在折叠屏 iPhone 上，让原生运行的游戏在每种姿态下都好玩——画面放在看得最舒服的地方，按键放在拇指够得着的地方，姿态变化时自动切换、游戏不中断。

**不做的**：不改游戏玩法、不做联网功能、不分发游戏内容。模拟器核心（改写器、宿主、NVN 到 Metal 的图形层、着色器翻译）交给上游 nxnative，Halfold 只在外壳和出图这一层做事。

**目标设备**：iPhone Duo（iOS 27.1）。设计上不写死 Duo，任何竖屏设备（普通 iPhone 竖拿、其他折叠屏）都应该能用同一套逻辑。

## 2. 架构：三层

```
┌──────────────────────────────────────────────┐
│ 折叠屏套件 HalfoldKit（dm/ios/Sources/Halfold/）  │  ← Halfold 的核心资产
│   姿态 · 布局 · 自转 · 按键方案 · 画质方案        │     不依赖宿主内部
├──────────────────────────────────────────────┤
│ 接入层（少量钩子，散在 nxnative 的外壳和出图里）   │  ← 越薄越好，争取提交回上游
├──────────────────────────────────────────────┤
│ nxnative 上游（改写器、宿主、图形层、iOS 外壳）    │  ← 定期合并，不动
└──────────────────────────────────────────────┘
```

为什么这样分：nxnative 一周 100 多个提交，核心文件（`nvn_mtl.m` 约 9000 行）改得很勤。折叠屏逻辑如果散在上游文件里，每次合并都要解冲突；集中在套件里，冲突只会落在几行钩子上。同一套套件以后还能接 d2r-mobile（同一个祖先，外壳结构相近）。

## 3. 套件模块

### 3.1 姿态（Posture）

输出当前姿态，供布局和画质使用：

| 姿态 | 判断依据 | 布局 |
|---|---|---|
| 展开横屏 | 内屏、界面横屏 | 全屏画面，按键叠在画面上（上游原样） |
| 展开竖屏 | 内屏、界面竖屏、铰链全开 | 画面上半屏，按键下半屏 |
| 半折立起 | 内屏、竖屏、铰链半开（`UIHingeInteraction` 的 `PartiallyOpen`） | 画面在立着的一半，按键在平放的一半，按键避开折痕 |
| 合上（外屏） | 外屏（按屏幕 `nativeBounds` 区分） | 外屏竖屏紧凑布局 / 外屏横屏 |

输入：铰链状态与角度（`UIHingeInteraction`，iOS 27.1 起）、当前屏幕、系统界面朝向、重力方向。铰链接口不给铰链在屏幕上的位置，目前按"竖屏时横穿正中间"处理（Duo 实测内屏每半边 1426×2007，和外屏比例一致）。

### 3.2 布局（Layout）

纯计算、可单元测试：输入姿态、屏幕尺寸、安全区，输出

- `pictureRect`：游戏画面区域（再按铺满方式放 16:9 画面）；
- `controlsRect`：按键区域；没有铰链横在中间时（外屏、普通 iPhone），等比模式下画面区域按 16:9 贴顶，按键区拿走剩下的高度，画面上方不留黑边；
- `hingeBand`：折痕附近不放按键的区域（半折时）。

实现：`hf_layout_make()`（`dm/ios/Sources/Halfold/hf_kit.c`），由 `front_ios.m` 的 `front_ios_layout()` 调用，按键视图的 `area` / `areaInsets` 取它的 `controls`。单元测试在 `halfold/tests/`（`make -C halfold/tests`）。

套件放在 `dm/ios/Sources/Halfold/` 而不是仓库根目录：每个游戏的 Xcode 工程用符号链接引用 `dm/ios/Sources`，放在这里才会被编进去；这是上游没有的新目录，合并上游不会冲突。

### 3.3 自转（倒拿纠正）

背景：用 iOS 27.1 SDK 编译的 App，系统不会转成倒置竖屏（锁屏、主屏幕和用新 SDK 的 App 会转）；Duo 内屏上 `UIDevice.orientation` 和界面差 90°、倾斜时常报平放，不能用。

做法（已实现：规则在 `hf_kit.c` 的 `hf_flip_update`，`front_ios.m` 的 `deviceTurned` 负责读传感器、存校准值、转视图）：

1. 加速度计低通得到重力方向（`DmGamepad.m` 的 `dm_gravity`，与摇手柄检测共用一路传感器）。
2. 机身与当前屏幕的角度差（以 90° 为单位）取进游戏后、或换屏后第一次稳定的竖屏读数（当作正着拿），不存盘。曾经用横屏读数校准并按屏幕存盘，但 iPhone Duo 上两次横屏读数差了 90°，存下的值让竖屏判断失效，已去掉（2026-10-26）。
3. 系统界面停在正立竖屏、而重力显示倒着拿时，把装着画面、按键、帧率的容器视图转 180°；系统自己转成倒置时不再重复转。读数稳定 0.4 秒才切换。

升级到 Xcode 27.2（据称开始支持 iPhone Duo）后要重新验证：系统若能原生倒置，这一层自动不起作用，可以保留作兜底。

### 3.4 按键方案（Control profiles）

- 每种姿态一套按键位置、大小、透明度；用户可在编辑器里拖动调整，按游戏、按姿态保存。
- 实现：`hf_profile_default()` 给每种姿态的默认方案（竖屏上抬 20%、内收 16 点、浮动左摇杆）；按键编辑器（布局按钮正下方的"编辑"，或长按布局按钮）在此基础上记录拖动、大小、透明度，按姿态存 `NSUserDefaults`。
- 用户反馈的痛点（按键太靠下、摇杆难握、底边点击被系统手势判定拖慢）都应能在编辑器里解决，默认值也据此设定。

### 3.5 画质方案（Picture）

- 出图层已支持 MetalFX 空间超分（`DM_UPSCALE`）和铺满方式（`DM_FIT`：等比 / 拉伸 / 裁切），对 NVN、Vulkan、OpenGL 游戏都生效（三者都走 `present_enqueue`）。
- 套件按姿态选择铺满方式：例如横屏默认等比，竖屏上半屏默认裁切或等比。
- 按游戏的渲染分辨率补丁（如哈迪斯 2 的 1080p，`dm/games/0100A00019DE0000/patches.py`）属于游戏配置，走上游的 `patches.py` 机制，能提交回上游。

## 4. 接入点（现状与目标）

| 接入点 | 现在在哪 | 作用 |
|---|---|---|
| 画面区域 | `front_ios.m` `front_ios_game_area()`，`viewDidLayoutSubviews` | 决定游戏视图放哪 |
| 按键区域与边距 | `DmGamepad.m` `area` / `padInsets` / `dm_gamepad_set_insets` | 按键排在哪块区域 |
| 触摸映射 | `DmGamepad.m` `pushGame` | 点画面映射到游戏触摸屏 |
| 舞台旋转 | `front_ios.m` `stage` + `deviceTurned` | 倒拿自转 |
| 出图选项 | `nvn_mtl.m` `present_fit_mode` / `present_fx_ready` | 铺满方式、超分 |
| 设置项 | `dm/games/settings.tsv`、`Launcher.swift` | 设置页上的开关 |
| 屏幕方向 | `dm/ios/project.yml`、`supportedInterfaceOrientations` | 允许竖屏 |

目标：收敛成两个通用钩子，尝试提交给上游——

1. **布局提供者**：外壳问"画面放哪、按键放哪"，默认实现等于上游现状，Halfold 注册自己的实现。
2. **出图选项**：铺满方式和超分作为出图层的公开选项（与上游 #215 的 MetalFX PR 协调，避免重复）。

钩子进了上游之后，Halfold 基本不用再改上游文件。

## 5. iPhone Duo 实测特性

| 项目 | 数据 |
|---|---|
| 外屏 | 1398×2034 像素 |
| 内屏 | 2007×2853 像素（竖），点缩放 3 |
| 铰链 | 竖屏时横穿内屏正中间；`UIHingeInteraction` 给状态与角度，不给位置 |
| 倒置竖屏 | iOS 27.1 SDK 编译的 App 不给；锁屏、主屏幕、部分 App 会转 |
| 设备朝向 | 内屏上与界面差 90°，倾斜时常报 FaceUp |
| 调试 | `xcrun devicectl device info displays` 看各屏 `currentOrientation`；`xcrun devicectl device capture screenshot --display-unique-id 123-456-789` 截内屏（截图含用户私人画面，用完删除） |

## 6. 待定问题

- Xcode 27.2：装在外置盘、用 `DEVELOPER_DIR` 调用；验证原生倒置和其他 Duo 支持。
- 铰链位置：目前假定在正中间；有接口后改用真实位置。
- 中文界面：上游要求全英文，Halfold 保留中文；若上游接受多语言方案再合并。
- d2r-mobile：触控层和画面耦合更深（腰带、菜单按画面 HUD 定位）。2026-10-26 试做了竖屏分屏 + 下半屏小地图，效果不好已取消（见 ROADMAP 第 5 阶段）。
